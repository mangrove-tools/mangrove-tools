# Budget Advisor Decision Canvas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Budget Advisor's manual channel form with a browser-only
historical-data Decision Canvas that models only defensible marginal response,
preserves unsupported channels, and exposes the curves and constraints behind
every allocation.

**Architecture:** Keep the static HTML, CSS, and vanilla-JavaScript deployment.
Add separate pure modules for history ingestion, marginality analysis, and
constrained allocation; extend the shared canvas chart module for evidence
views; and keep `analytics/budget/app.js` limited to state and DOM
orchestration. Raw imported rows remain in browser memory and never enter
telemetry, persistence, or network requests.

**Tech Stack:** Static HTML5, CSS, vanilla JavaScript using browser globals,
Canvas 2D, Node's built-in test runner, Python 3 `unittest`, existing
repository validator

## Global Constraints

- Scope is Budget Advisor v2 at `/analytics/budget/` only.
- Keep all calculation and imported data in the browser.
- Do not add a framework, runtime dependency, build step, account requirement,
  backend, database write, server-side input handling, or raw-input
  persistence.
- Do not change Affiliate IDs or `AFFILIATE_URL`.
- Do not change Google Analytics identity.
- Do not change Supabase schema or backend behavior.
- Do not change Vercel, DNS, domain, production wiring, payments, secrets, or
  legal claims.
- Do not change Revenue Forecaster behavior or unrelated routes and
  calculators.
- Preserve current `main`'s shared-asset fingerprinting contract. Edit the
  canonical shared source, generate the matching 12-character SHA-256
  fingerprinted copy, and update every public reference atomically.
- Do not fit, display, or optimize against a generic substitute curve for an

- [ ] **Step 3: Implement pure statistical helpers**

Implement and keep private:

```js
function quantile(sorted, probability) {
  const position = (sorted.length - 1) * probability;
  const lower = Math.floor(position);
  const upper = Math.ceil(position);
  const weight = position - lower;
  return sorted[lower] * (1 - weight) + sorted[upper] * weight;
}

function predict(curve, spendRate) {
  if (!curve || !Number.isFinite(spendRate) || spendRate <= 0) return 0;
  const value = curve.a * Math.pow(spendRate, curve.b);
  return Number.isFinite(value) && value >= 0 ? value : 0;
}

function marginalOutcome(curve, spendRate) {
  if (!curve || !Number.isFinite(spendRate) || spendRate <= 0) return 0;
  const value = curve.a * curve.b * Math.pow(spendRate, curve.b - 1);
  return Number.isFinite(value) && value >= 0 ? value : 0;
}
```

Fit `log(outcome) = log(a) + b * log(spend)` with ordinary least squares over
positive observations. Report log-space `r2`; never call it confidence or
accuracy.

- [ ] **Step 3: Implement horizon and constraint normalization**

Set `horizonFactor = planDays / model.cadenceDays`. Convert every historical
spend rate to a plan-total amount with that factor.

For an excluded channel, set effective minimum and maximum to zero. For a
preserved channel, set both effective minimum and maximum to the explicit
minimum when provided, otherwise to
`preservedSpendRate * horizonFactor`. For a modelable channel, default minimum
to zero and maximum to infinity.

Return a controlled failure before optimization when:

- total budget or plan days is not finite and positive;
- a minimum is negative;
- a maximum is below its minimum;
- effective minimums exceed the budget;
- finite effective maximums are below the budget; or
- a positive remainder exists with no modelable capacity.

- [ ] **Step 4: Implement marginal balancing**

Reserve effective minimums. Allocate the remainder only across modelable
channels. For a proposed plan-total spend `S`, evaluate its curve at
`S / horizonFactor`. Because the same horizon factor multiplies both predicted
outcome and spend, the marginal derivative is the curve derivative at that
spend rate.

Use a monotonic bisection over a shared positive raw-marginal threshold. For
each channel with curve `{a, b}`, calculate its unconstrained spend rate as:

```js
Math.pow((curve.a * curve.b) / threshold, 1 / (1 - curve.b))
```

Convert to plan-total spend, clamp to effective minimum and maximum, and search
until the summed allocation is within `0.001` of the budget or 200 iterations
complete.

For a before-marketing contribution objective, allocation is unchanged because
subtracting the fixed total budget is constant across feasible allocations.
Only predicted net contribution and marginal ROI subtract marketing cost.

- [ ] **Step 5: Reconcile currency and construct controlled results**

Round plan allocations to integer cents. Reconcile the remaining cents one at
a time only across channels with remaining capacity, ordered by modeled
marginal outcome and then channel name for deterministic ties. Return a
controlled failure if reconciliation cannot satisfy the exact requested cents.

Metric rules:

```js
function marginalMetric(metric, rawMarginal) {
  if (metric.key === 'conversions') {
    return {
      key: 'marginal_cpa',
      value: rawMarginal > 0 ? 1 / rawMarginal : null
    };
  }
  if (metric.key === 'revenue') {
    return { key: 'marginal_roas', value: rawMarginal };
  }
  return {
    key: 'marginal_roi',
    value: metric.costTreatment === 'before_marketing'
      ? rawMarginal - 1
      : rawMarginal
  };
}
```
